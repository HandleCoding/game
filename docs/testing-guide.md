# 云端测试与验收

测试工作区 `/opt/pair-play-dev`。正式 3210、开发 3211、当前 HTTP 集成测试固定 3221。集成测试创建系统临时目录，不使用正式或开发持久数据库。

## 当前自动测试命令

```sh
cd /opt/pair-play-dev
flock -n /run/lock/pair-play-dev-tests.lock env -u PUBLIC_ORIGIN -u DATA_DIR -u PORT NODE_ENV=test HOST=127.0.0.1 npm test
```

清除上述环境变量，防止调用者把正式 PUBLIC_ORIGIN 等带进测试子进程。集成测试本身为子服务指定 PORT=3221 与临时 DATA_DIR。锁失败表示已有其他 Agent / 测试占用，先确认，不启动另一组去争同一端口。正常运行约 15–30 秒，包含真实等待邀请 15 秒过期，不应以尚未完成判断卡住。

代码还可以做语法检查：

```sh
node --check server.mjs
node --check game.mjs
node --check public/app.js
node --check public/theme.js
```

当前 Node.js 会提示 `node:sqlite` 实验特性；该提示本身不表示测试失败，以退出码和 TAP 结果为准。没有前端构建 / TypeScript 检查命令，目标框架接入后补齐。

## 当前 11 项覆盖

规则测试 10 项：位置匹配和数字边界；双人准备和秘密锁定；骰子平局 / 先手；回合权限和胜利；超时；断线暂停 / 恢复；双方离线与重开；记忆模式隐私；前导零与最新对方猜测；两种模式各种结束原因的完整复盘与重开清理。

HTTP 集成测试 1 项：真实注册 / 登录、错误密码、未登录、恶意 Origin、目录 / 在线状态、邀请接受 / 拒绝 / 15 秒过期、容量 / 设置权限、秘密隐私、完整对局、记忆模式、进程重启恢复、离开结果和退出登录。

自动测试不等于已经验证动画、全部屏幕尺寸或 PostgreSQL 迁移。每次报告必须区分自动通过、浏览器通过和仍未验证的项目。

## 双端浏览器验收

仅在开发环境注册两个不同测试账号，用两个独立浏览器会话 / 配置文件分别登录。不要在正式库创建大量测试账号。创建房间与邀请后按下表验收：

| 场景 | 验收点 |
| --- | --- |
| 电脑 + 电脑 | 大厅 / 在线状态、邀请、规则、轮流输入、历史与复盘 |
| 手机 + 手机 | 触控、数字键盘、固定输入、视口与键盘切换、无横向溢出 |
| 电脑 + 手机 | 同一对局状态、剩余时间 / 回合一致、跨设备输入和同步 |
| 日间 + 夜间 | 背景、文字、按钮、弹窗和不同命中提示均清楚 |
| 查看记录时输入 | 草稿、焦点、输入框与历史滚动不被 SSE / 筛选重置 |
| 对方回合预写 | 可输入草稿，不能提前提交；轮到自己边框提示 |
| 记忆模式 | 进行中无完整历史，最新对方猜测更新；结束后双方完整复盘 |
| 前导零 | `0000` / `0123` 能保存和提交，不转为整数 |
| 骰子 / 命中效果 | 平局重掷、最终点数正确，命中 0–4 的提示；减少动态效果 |
| 后台 / 断网 | 断线暂停、60 秒内重连恢复；超期按规则结束 |
| 开发服务重启 | 仅重启 pair-play-dev，活动房间与私有数字恢复 |
| 安全视图 | 对手秘密仅结束后揭晓，HTTP / SSE 都不能提前包含它 |

手机验收需先建立手机可访问的独立开发入口，目前仅 SSH 转发入口已配置。不能用电脑的手机视口模拟替代真实手机键盘 / 后台切换验证；模拟可以作为补充，报告注明设备或模拟方式。

## 目标架构必须新增的测试

- 注册表 / gameId / 版本恢复；不同游戏、多房间不串数据，2 人与多人席位竞争。
- 请求去重、旧 matchId / revision 拒绝、结果只入账一次；平局 / 团队结算。
- SQLite → PostgreSQL 的 ID、密码、会话、关联、快照迁移与恢复演练。
- 农场首次初始化唯一、同一地块多设备并发收获一次、资源事务、负余额防护。
- 离线成长、跨重启补算、成长规则版本、产能 / 饲料 / 容量限制。
- 主人 / 访客视图与互动权限，重复作业执行不重复发货。

测试要针对实际风险，不为纯文案 / 可逆低影响变更堆镜像实现的断言。新增实际规则或修复缺陷时添加能捕获回归的案例。
