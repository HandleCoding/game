# 牧场变异、品质、名宠融合：2.8.0 实施交接

源码目录 `/opt/pair-play-dev`，沿用 Vue 3/TypeScript、Fastify/Node.js/TypeScript、PostgreSQL 18。正式地址 `https://game.aicoding.ltd/`。实现分支 `codex/ranch-mutation-implementation`。本文件记录实际实现；原设计与模拟见 ranch-mutation-implementation-plan.md、ranch-mutation-balance-simulation.md。

## 本次范围

购买与成年各一次独立变异；五档品质、五种属性、双属性、产物溢价与小数守恒；真正发现的图鉴；有限生产后的名宠融合；晶露、珍藏保护、库存锁定、收集目标。保留 36 种动物、2.7.0 成长/生产/耗粮/终身轮次与账号进度，不加入训练养成、作物、交易、充值、偷取或新的死亡机制。

## 规则与数值

每次机会独立使用服务器当前概率：基础10%，完成养殖物种达到6/12/18/24/30种各+2个百分点；发现的非空属性组合达到10/30/60/100/150各+2个百分点；最多30%。若两次都按10%，至少一次成功为19%、两次成功为1%；都按30%则为51%、9%。跨越里程碑后第二次可能用更高概率，不能把19%/51%说成所有玩家固定终身概率。

属性权重：雷25、火25、水25、黄金15、梦幻10。第二次成功排除已有属性，最多两种，顺序不构成新品种。品质取两次成功结果的最高值，普通/优秀/史诗/传奇/无双分别白/绿/紫/金/红。失败也永久记录机会已使用，刷新、重复请求、重启不能重抽。预览不消耗随机数。

品质权重按个体 `growthMs + maxRounds × cycleMs` 划分：

| 生命周期 | 普通 | 优秀 | 史诗 | 传奇 | 无双 |
|---|---:|---:|---:|---:|---:|
| ≤2小时 |40%|42%|15%|2.9%|0.1%|
| >2～24小时 |36%|42%|17%|4.5%|0.5%|
| >24～72小时 |32%|42%|18%|7%|1%|
| >72小时 |28%|40%|20%|8%|4%|

生产批次冻结当轮品质、属性与价格。品质加价0/10/25/50/100%；雷/火/水各5%，黄金10%，梦幻15%，属性合计上限20%；总价上限基础价2.2倍。品质/属性不影响成长、耗粮、经验、生产轮次。价格为每单位千分之一金币的整数，结算用 BigInt；钱包仍整金币，余数0～999另存。出售后余数累计，拆单不损失也不创造收益。旧库存按原价，不随新变异涨价。

晶露不是每件产物都掉落：功能生效后的真实生产轮次，每只动物每个北京时间生产日最多1，账号同日最多3；只在实际收获时入账。按生产日计数，离线回来不能将多天生产挤进当天/覆盖旧日计数。赠送批次与功能生效前批次不补发。

名宠融合仅自己的、完成生产且已进入名宠堂、同物种同品质、未珍藏且无存货的伙伴。100%成功，只提高一级：

| 目标品质 | 材料数量 | 基础晶露 | 金币（目录认养价比例，向上取整） | 随机属性额外晶露 |
|---|---:|---:|---:|---:|
| 优秀 |2普通|0|10%|1|
| 史诗 |2优秀|3|25%|2|
| 传奇 |3史诗|12|50%|4|
| 无双 |3传奇|48|100%|8|

主伙伴保留 ID、昵称、原成长档案，材料转 `fused` 状态并保存融合快照与日记，绝不 DELETE。不会恢复生产、重新给经验、返还已消耗材料或重估旧产物。无双不能继续融合/同级重抽。继承保持主伙伴属性；随机时无属性/单属性抽一项，双属性先选择保留一项、另一项按排除池重新抽。随机仍可能得到原来的属性，不承诺必不同；不会借材料让单属性主伙伴变为双属性。

图鉴键为物种+排序后的属性集合，品质记录该键真正达到的最高品质。普通发现、预览、访客、重复发现均不算额外变异品种。历史已发现普通物种保留，但不虚构过去变异。六种收集目标最多追踪3项，无额外金币/经验/晶露奖励，避免奖励循环。珍藏阻止出售、放生和融合；库存锁定阻止出售，全部出售只处理未锁定项。

## 源码地图

- `apps/api/src/games/animal-ranch/mutation.ts`：安全随机、两次机会、图鉴、概率、晶露、定价、目标、融合规则/预览。
- `engine.ts`：按真实成年和生产游标结算，状态视图、批次冻结、库存出售小数守恒与动作。
- `storage.ts`：钱包/个体/批次/库存/图鉴/材料/融合同事务保存；每次结算只加载活跃动物和明确目标，收藏用20条键集分页。融合列表服务器过滤物种/品质/珍藏，前端按需“加载更多”，不一次下载整个名宠堂。
- `platform/persistent.ts`：玩家档案锁、revision、requestId 回执与只读融合预览；`main.ts` 限定预览请求结构和最多3个材料。
- `platform/db/migrate.ts`：schema5；`packages/contracts/src/ranch.ts`：公开/私有视图协议。
- `RanchCollection.vue`：真实图鉴、目标和按冻结价格/品质/属性/锁定分组的仓库，最多200个批次ID一组，支持指定数量。
- `RanchFusion.vue`：材料、主伙伴、属性选择、服务器费用预览、二次确认、分页。
- `RanchTraits.vue`、`ProductIcon.vue`：品质/属性提示、原生SVG产物类别；`RanchScene.vue`：每属性4～5个轻量粒子，双属性最多9个；雷弧/火焰/水波/金色星光/梦幻光点，动态材质叠加属性色泽和柔和光泽，保持原图透明轮廓与阴影，裁切帧缓存最多96个，保留柔和写实动物与侧边食槽。
- `ranch-modern.css`：现代简洁浅色/深色弹窗、绿色操作按钮、清晰留白；手机底部弹层、桌面并列详情，横屏缩紧标题，减少动态效果时静止。

HTTP `POST /api/games/animal-ranch/fusion-preview` 只校验和返回费用/结果预览，不推进存档、不扣费、不抽随机、不写回执。正式融合走原 action 接口。客户端30秒网络超时保留原请求ID/原revision/原参数；服务器已提交却返回503或断网时，重试同一动作读取原回执，不能再抽一次或再次扣款。确定的4xx清除待重试；有未确定请求时阻止发送不同操作。

## 持久化与迁移

schema5新增 `ranch_features`（生效时间、晶露、金币余数、追踪等）、`ranch_codex`、`ranch_material_daily`、`ranch_fusions`；扩展动物状态约束允许 `fused`。原账号、会话、猜数字结果、档案、钱包、动物和库存不清空。**摘要存档仍version2**，新结构在独立表中；这与早期计划的version3不同，是实际实现选择，不需要为摘要重编号进行额外迁移。

迁移时为已有钱包写入唯一生效时间；旧动物购买机会跳过；已成年/名宠堂不补抽成年机会；旧幼年只有真正于生效之后成年才有一次成年机会。旧赠送和库存保值，无追溯补发晶露或溢价。同一迁移可重复执行，机会状态持久化。新增数据和动作回执均在同一 PostgreSQL 事务内；失败原子回滚。

访客只看到允许公开的个体品质/属性；不返回钱包、库存、晶露、概率、目标、融合材料、私人变异失败记录和保护状态。融合选择ID仍由后端重新验证所有权、同类、数量、生命周期、珍藏和当前资源，不能信任预览/客户端字段。

## 开发与验收

全部在京东云开发目录执行。环境 `/etc/pair-play/dev.env` 不得打印或提交；测试强制 `playroom_dev`，每次随机独立schema，HTTP端口3221用 `/run/lock/pair-play-dev-tests.lock`；测试结束清理其创建的临时schema，与真实玩家表隔离。

常规命令：`npm run typecheck`、`npm run build`、`npm test`。外观专项 `node scripts/ranch-mutation-appearance-qa.mjs` 实际比较Canvas像素、验证五种属性与双属性在幼年/成年均有可见差异且不涂染整个背景，减少动态效果时保持静态材质。

专项 `npx tsx scripts/ranch-mutation-simulation.ts`、`node scripts/ranch-mutation-ui-qa.mjs`；原场景 `scripts/ranch-ui-qa.mjs`、名宠堂 `scripts/ranch-hall-ui-qa.mjs`。浏览器使用 `UI_BROWSER` 与 `UI_BROWSER_EXECUTABLE`，旧UI回归设 `UI_REPORT_PREFIX=20261005-ranch-mutation-scene` 或 `...-hall`，不能覆盖历史验收报告。执行前读取 testing-guide 环境加载/加锁命令。

数值模拟 `docs/test-reports/20261005-ranch-mutation-simulation.json` 使用实际引擎、固定种子20261005，4档寿命×10%/30%×50000只=40万样本，验证两次概率、双属性、溢价上限。旧设计模拟报告保留，不能把其样本量当成本次实际引擎样本量。自动化覆盖原玩法、旧存档、两次抽取、晶露跨日、库存余数、锁定、预览只读、跨用户权限、并发融合去重、异常回滚和重启恢复。手机/桌面浏览器为320/390/430竖屏、844横屏、1440桌面模拟，不能称真机验收。

最终测试状态、截图和正式发布记录见 `test-reports/20261005-ranch-mutation.md`。

## 发布与故障处理

提交已验收运行源码、检查构建与真实服务，再用 `python3 scripts/release-postgres.py --deploy --ranch-mutations`。脚本关闭game入口、复查无猜数字对局、停正式写服务、取得最新PG备份后启动新代码和迁移；检查schema≥5、features与钱包数量一致、钱包快照保持、账号/会话/历史数量及健康/资源。**本次禁止 `--reset-ranch`**。备份不进入Git。

schema5后原2.7会忽略冻结价格/融合状态，不能自动旧代码回滚；迁移或验证失败须保持维护、备份、前向修复。恢复用同次备份原Caddyfile，保留 `/ranch-3d/*` 小样路由和其他域名。独立3D小样属于另一Agent工作，本实现不提交、替换或接入其文件。Milvus与其他服务保持。

后续新增属性/配方需递增规则或配方版本，保存当时的价格与来源；不能重抽旧伙伴或按新配置追溯改旧批次。进一步加交易/互助需要跨档案锁序和额外经济模拟，不套单档案动作锁。
