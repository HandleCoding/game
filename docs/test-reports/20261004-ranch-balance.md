# 一起牧场数值重做（2.6.0）

2026-10-04，京东云 /opt/pair-play-dev 开发；数值规则版本 2，持久档案协议仍为 1，数据库 schema 3。正式发布结果见本目录 release.json。用户明确允许重置其唯一线上牧场，账号、会话与猜数字数据保留。

## 原因与方案

旧配置把旧牧场的“小时”按 30 秒压缩，导致小鸡 4 分钟成年、3 分钟产出；每只每分钟消耗一份饲料，升一级固定 80 XP、扩建又便宜且给经验。数量扩张、分钟级产出、线性门槛叠加造成一下午解锁全部。实际核对生产仅储存产物，经验由收获得到，未发现本轮离线重复发经验的问题。

新的目标是每天回来 1–4 次仍能经营，全部 36 种属于数周至数月的目标。首日可收获赠送的小鸡鸡蛋、认养幼崽；新幼崽采用小时级周期。每只 30 分钟消耗一份饲料，初始 240 份、四只可吃 30 小时；1000 份满槽供 16 只可吃 31 小时 15 分。缺粮暂停、不死亡，不追补饥饿时间。三轮存量上限保留。

经验逐级增加；认养、送别、添粮、出售产物、扩建不加经验。扩建必须满足等级和金币双重条件。除新手小鸡外，售价按成熟后每日扣除饲料的净收益约为认养价 28% 校准，而不是所有动物每几分钟返还约四分之一购价。收获仍按每份产物给经验，高价动物不保证最优经验效率。

参考中文 GameRes 的[从0开始的数值设计实战](https://www.gameres.com/forum/t/880814)中先定义成长节奏、再用产出消耗推导验证的流程，以及[经济系统产出、消耗与成长关系](https://www.gameres.com/659627.html)。这些用于设计方法；本次数值由独立引擎模拟校准，不能标注为最新微信 QQ 农场官方数值。

## 验证方法

- npm run typecheck、npm run build。
- 云端开发库隔离 schema 的 npm test，25 项通过：原猜数字/认证/并发/迁移继续验证，新增经验边界、极限上界、饲料/分段守恒、小时周期、重复买卖零经验、扩建门槛、经济净收益和 180 天模拟。
- node scripts/ranch-reset-qa.mjs 实际 operator CLI 重置、600私有快照、玩家数量不符中止与局部恢复通过。
- 真正 relational reset / restore 演练覆盖钱包、动物、仓库、流水、动作回执；用户与其他游戏数据保持，revision 增加，旧动作拒绝；预期用户数量变更则终止。
- 手机 320/390/430 竖屏、844 横屏、1440 桌面分别运行 Chromium 与 WebKit，最终各5/5通过、共10组。新增小时/天倒计时、30 分钟耗粮、Lv.3 扩建门槛的页面断言。模拟视口，非实体手机。
- 初轮 Chromium 4/5：仓库断言在收获响应完成前执行，430px 失败。改为等待真实库存选中节点再断言；下一轮新增的时长断言误将恰好“5天”判为无小时，修正为允许天/小时，再完整验证两引擎，不通过放宽规则掩盖问题。
- 2.5.3 图片/切图/慢网逻辑未修改；本次 UI 仍验证图片加载、幼年/成年与动画。未额外重复所有慢网/图集专项。

模拟脚本 scripts/ranch-balance-simulation.ts 调用真实 initial / settle / action，不自行重写收益计算；模拟会按策略选购/替换、保留饲料预算、等级与资金允许时扩建。它并非全局最优解，也不等于玩家必然达到的日期。对照包含每 15 分钟关注经验、每 6/12/24 小时关注收益的四种策略。各 180 天模拟补粮为零缺粮访问，至少证明该策略下不会经济死锁。最优理论上界假设开局即有 16 只最快经验成年动物且无限饲料；它用于证明不能一下午全解锁。

## 发布与数据边界

日常发布不重置数据。仅本次经用户授权执行 scripts/release-postgres.py --deploy --reset-ranch；关闭游戏域名入口、停止应用后生成最新完整备份与仅牧场私有快照，然后同一事务重新初始化唯一牧场。没有公开重置按钮/接口。

重置保留原 persistent_profiles 主键，并 revision +1；移除该牧场旧钱包/动物/仓库/流水与 persistent:animal-ranch 动作回执，初始化 800 金币、240 份饲料、4 位置、一只成年小鸡与 3 份鸡蛋。guess-number 回执、账号密码、登录会话、对局/复盘不动。若维护期间验证失败且入口尚未恢复，仅恢复备份里的牧场行；不覆盖整库。开放后禁止直接回滚旧快照丢失新进度。

已有动物保存购入时周期，普通后续商店改价不追溯变更实例；新增 feedUnitMs 保存在轻量摘要，缺失时按旧一分钟单位读，避免无授权自动转换存档。本次唯一真实旧存档经授权清空，重新按新规则开始。
