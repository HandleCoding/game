# 2026-10-04 正式公网慢速加载修复（v2.5.3）

## 故障与证据
用户在正式版2.5.2看到0/6资源、随后加载失败。旧实现是整张图25秒定时取消，开发本机加载与路由延迟检查未覆盖持续慢速正文传输。
从Windows电脑用Invoke-WebRequest实测正式原背景PNG：HTTP200、2,922,830字节、74.85秒。服务器公网自己下载该图约6.13秒，而云端回环测试更快。完整PNG签名与正文有效，不是路径404或CSP失败。此次实测单文件已经超过旧25秒限时，六图并发更容易被整批中断。

## 修复
- fetch读取真实响应流，每块数据更新该资源的下载比例；百分比为所需资源各自完成比例的平均，下载完成之后保留解码阶段，只有解码成功计入“项资源已就绪”。不是字节总和百分比或计时动画。
- 超时改为连续45秒无数据；持续有数据的正常慢速传输不受25秒总时长限制。取消与卸载通过AbortController和Promise.race收敛，成功图像保留供重试。
- 必要图片最多两个并发；首屏HUD未就绪时不挂载，避免隐藏SVG再发一份工具图集请求。
- 11张现有PNG提供版本化无损WebP。可见像素、透明度与尺寸逐像素验证相同，原PNG保留；总下载体积19,346,034→14,393,608字节，减少25.6%。仅版本化公共文件长期缓存，HTML/API和CSP不弱化。将来改图必须用新版本文件名。
- 使用现有data:图片许可完成解码，不新增blob:或外域许可。游戏规则、数据库与存档不变。
