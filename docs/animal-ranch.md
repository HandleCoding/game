# 一起牧场：实际实现与接手

2026-10-04，客户端日期 Asia/Shanghai。新增 ID animal-ranch，kind=persistent，version=1；当前应用版本 2.6.0 / 数据库 schema v3。用户要求先养动物，首版 30+ 种、不同等级和周期；实际 36 个独立物种。未加入作物种植。

## 入口与玩法

大厅新增一起牧场卡片，登录后进入个人存档；也可使用 /?game=animal-ranch。无需开房、准备或邀请才能玩。离开界面、参与猜数字不重置进度。在线状态显示一起牧场 / 正在游玩，同时仍可接受短局邀请。

800 金币、240 饲料、4 个位置、1 只带 3 份鸡蛋的成年小鸡。认养幼崽 → 食槽自动喂养 → 成长产出 → 收获仓库 → 出售 → 升级 / 扩建 / 解锁新品种。36 种按家禽家畜、萌宠、动物园分类、按等级逐步解锁；可分类、搜索和仅看已解锁。

所有已有牧场可从串门目录参观，包含离线玩家，无加好友机制。首版只读，不支持偷取、帮喂、交易、赠送。访客视图不返回金币、经验数值、饲料数量、仓库和私人日记。

## 数据与事务

通用 persistent_profiles 保存存档版本、revision、结算时间和轻量摘要 version / at / feedUnitMs。PersistentDefinition 增加可选 storage.load / storage.save，供牧场以结构化表加载保存；旧的纯 JSON 测试游戏兼容。

- ranch_wallets：非负金币、经验、饲料毫秒、4–16 偶数容量、下一个动物编号。
- ranch_animals：每只独立行，私有 JSON 保存物种、年龄、积攒产量及购入时周期 / 产量 / 产物 / 实际价格 / 收获经验。不是把整个牧场放进一个房间快照。
- ranch_inventory：每种产物数量有非负约束。
- ranch_ledger：购买、饲料、收获、出售、扩建的日记和金币变化，不删除旧流水；页面展示最近条目。
- action_receipts：重复请求只执行一次；expectedRevision 防止两台设备覆盖。
- 全部与档案 SELECT FOR UPDATE 在同一事务提交；失败整体回滚。访客读取也会按规则结算后裁剪公共视图。

schema v3 扩大食槽毫秒预算上限；v2 仅添加新表和索引，不重建原 users / sessions / results / active_rooms。数据库迁移和新增游戏都不导入开发 QA 用户到正式库。

## 时间与资源

时间来自服务器，settle 将离线经过时间限制在食槽实际可供给的时间；新牧场每只每30分钟一份，共享饲料。累计量最多三轮，缺粮暂停、不死亡，补粮从当前时间继续，不追补饥饿期。

保存实例参数，未来调整商店不能修改已有动物周期。读和动作都会结算；离线不用定时器不停写数据库。onMounted / visibilitychange / 15 秒轮询刷新，倒计时只展示。提交后只给主人 SSE persistent-change 提示，各设备重新读取权限视图；轮询作为重连补偿。

牧场浏览 presence 为临时在线信息（60 秒租约），不作长期游戏开局计时，离线即清理；短局房间状态优先，仍沿用双人游戏邀请逻辑。

## 可玩性调研草案（2026-10-04，尚未实施）

用户明确要求三个子 Agent 分别探索日常目标、经营和社交；下述是综合建议，不是已上线功能。2.6.1 只修复 HUD 提示遮挡，不增加玩法、重置或修改数值。

### 当前短板

目前主要循环为认养→等待→收获→出售→解锁。把分钟级成长改成小时后，等待合理了，但还缺少等待期间可玩的互动、不同用途的产物和可见的场景变化。现图鉴统计等级解锁，并非真正养过的永久收藏；36 物种和最多16个位置也容易迫使玩家为图鉴卖掉喜爱的动物。不要用重新加速成长、点击刷经验或堆叠每日签到弥补这些缺口。

### 推荐第一批：让动物有感情，让牧场有变化

| 功能 | 玩家做什么 | 得到什么 | 范围 |
| --- | --- | --- | --- |
| 名字、亲密度与互动 | 起名字、摸摸、梳毛、玩玩具 | 靠近、跟随、爱心、休息姿态、纪念照 | 先做小鸡/兔/狗代表动作；其他物种可用现有步态和反馈，不声称36种独立新动作已完成 |
| 永久成长日记 | 留下首次认养、成年、首次收获、合影 | 自己真正养过的收藏与回忆 | 送别后保留记录；区分等级解锁与实际收藏 |
| 可选委托板 | 在出售与交委托之间选择 | 少量金币或不交易的装饰兑换奖励 | 建议3个可选目标，按已有物种/产出生成；无产物时提供观察/照顾目标；可跳过，无罚款 |
| 场景小装饰 | 选择花盆、名字牌、宠物窝、玩具位置 | 牧场外观变化，动物会靠近使用 | 固定3–5个位置起步，不先做自由搭建编辑器 |

首轮体验建议：给成年小鸡取名→互动→收初始3个鸡蛋→选择交一份委托或出售→放置小木牌→认养幼崽→选下一次回来的目标。已有初始产物用于引导，不新增可反复领取的资源。第一批只做少量可见且有反应的玩法，保持沉浸式场景和手机大触点，面板用现有木质窗口。

### 第二批：异步串门互助与合作

保留“不加好友，所有注册玩家都能串门”。对方离线也可帮忙梳毛、清理、留固定短语和合影。主人主动开启求助，奖励限制按服务器账号/日期/玩家组合计算；不要求邀请人数，不强迫双人同时在线。首先不扣对方饲料、不偷对方仓库产物，也不给无限经验。

后续可选72小时合作委托：单人也有个人任务，合作目标按真正参与者的已有动物产出计算并锁定；贡献独立记录，奖励按贡献结算。需先模拟目标、退队、到期、部分完成和退款，不能先按“2人12鸡蛋”等未经验证的样例上线。真正偷取如未来要做，应单独讨论主人授权、保护额度与共享额外产物。

### 第三批：产物加工与少量饲草

先做鸡蛋点心、奶酪、毛线等少量配方，让库存有用途选择，再加两块饲草地辅助饲料。加工采用独立短周期，不缩短动物小时周期；草地不枯死、不强制高频照顾。访客投影、找玩具、蝴蝶/羽毛收藏及主题合影作为后续小活动。避免先上复杂疾病、动物死亡、连续签到处罚、金币排名或大规模作物系统。

### 数值与架构边界

经验仍只由收获获得，亲密互动和委托优先给外观/收藏进度，亲密度不直接乘产量。任何金币奖励、加工差价、饲草节省都需重新跑实际引擎的金币与等级模拟，核对1/7/30/90天和6/12/24小时回访；目前未决定固定奖励百分比。单玩家命名/日记/委托/装饰可扩展 animal-ranch 的引擎、结构化存储及同一档案事务，继续 requestId/revision/服务器时间；不需要换后端语言。

跨玩家动作需新专用服务及多档案有序行锁事务，同时验证两方权限、版本和重复请求。现 persistent.action 是同步单档案锁，不能只放开访客按钮或调用两次独立 action 当作原子互助。world_jobs 尚未实现；普通委托刷新、到期与成长可先访问时结算，不引入浏览器计时发奖励。相片先保存在游戏内，分享链接另议，不向外部自动发消息。
